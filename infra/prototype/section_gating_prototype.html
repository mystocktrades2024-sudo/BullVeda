★ LAYER 1 · REGISTRY (declarative)

        
JSON defines which roles can see which sections. Admin edits via CapStudio UI. Source of truth for both frontend + backend.

      

      

        
⌬ LAYER 2 · FRONTEND (render-time filter)

        
When tab renders · loops sections · checks section.roles.includes(userRole) · skips disallowed ones. Hidden sections never appear in DOM.

      

      

        
⚿ LAYER 3 · BACKEND (defense in depth)

        
Section data endpoints (e.g. /api/options/strategy_matrix/{ticker}) check role server-side · return 403 if denied. Cannot be bypassed by editing frontend JS.

      

    


    

      
⚙ LAYER 2·b · USER OVERRIDES

      

        On top of role-default, users can opt OUT of sections they don't care about.
        Stored in data/users/{username}_preferences.json. Try toggling:
        

          IV Smile
          Max Pain
          UOA Flow
        

      

    


    

      
🔒 SERVER ENFORCEMENT (Layer 3)

      

        Backend endpoints like /api/options/strategy_matrix/{ticker} check
        can_see_section(role, "options.strategy_matrix") before computing.
        Returns 403 if role isn't allowed. Free user editing JS to remove the
        frontend filter still can't get the data — server refuses.
