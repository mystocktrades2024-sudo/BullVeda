Why Supabase at all? It's the cloud read-layer for the public dashboard (trade.mystockholding.com) + the long-tail /api/ticker fallback — so any ticker resolves even if it's not in the local 300MB bundle. The scan writes locally first (fast, authoritative); Supabase is the mirror.

The sync is normalized: sync_scan explodes the bundle into a parent ticker_analyses row (per scan, keyed by analysis_id) + ~50 child tables (one per domain: technicals, fundamentals, options, decision, etc.). ~1,837 tickers × ~50 tables ≈ the 12-min write we backgrounded so it no longer blocks the dashboard.
