⚠ Guardrails — what this is not

Per CLAUDE.md: no new data licenses, EODHD single-source, respect your workspace.

Not a scoring data feed policy

TV quotes / screener / indicators must never route into the 5-pillar scoring path. EODHD is the single source of truth; two contradictory feeds is a bug, not a feature. TV = visual/authoring only.

Scratch-tab isolation lesson

The CLI targets the first chart tab and CDP target IDs rotate, so commands can land on a saved layout. Fix: the shipped script pins one target by symbol and never writes to a chart it didn't open.

Unofficial bridge tos

Community tool, not affiliated with TradingView or Anthropic. It automates your logged-in app (no scraping, no new account) — subject to TradingView's Terms of Use.

Run it

  1. Install the bridge (one time): git clone https://github.com/tradesdontlie/tradingview-mcp.git ~/tradingview-mcp && cd ~/tradingview-mcp && npm install
  2. Launch TradingView with the debug port: ~/tradingview-mcp/scripts/launch_tv_debug_mac.sh
  3. Push levels for any cached ticker/mode: node infra/prototype/tv_bridge/push_levels.mjs NEM swing
  4. For a persistent Claude session, register the MCP: claude mcp add tradingview -- node ~/tradingview-mcp/src/server.js then use tv_health_check
Why the MCP form is better than the CLI: the long-running MCP server holds one stable CDP target for a whole session, so the first-tab / rotating-target-ID problem disappears. The standalone scripts here exist so the integration works without restarting Claude Code.
Heads-up: this TradingView build swallows the programmatic Cmd+T new-tab shortcut, so a scratch chart must be opened by hand (or an existing tab reused + auto-restored).
